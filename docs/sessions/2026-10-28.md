# Session 2026-10-27 to 2026-10-28

## Goal

Build milestone M2 (sign-in, organization, onboarding) from the approved plan, one task per pull request, with independent security reviews of the auth-critical parts.

## Done, with evidence

- M2-01 to M2-11 merged as PRs #16-#33 (plus Dependabot). Two sessions worked in parallel for part of it; the overlap was one duplicate of M2-05, which was closed (#28) because `main` already had the same work.
- Backend: 541 unit and 383 integration tests (real PostgreSQL and Redis) — PASS. Frontend: 143 vitest, 250 Playwright against a mocked API (four languages, two themes, desktop and phone, axe WCAG 2.2 AA) — PASS.
- Real stack (Caddy over HTTPS, web app, API, PostgreSQL, Redis, a development Keycloak): `make test-stack-e2e` 46 tests — PASS; `make test-sso-dev` 35 checks and `make test-compose` 72 checks — PASS. All three run in CI (14 required checks).
- Independent security reviews: sessions/CSRF/proxy trust (M2-03b), local accounts (M2-04), single sign-on (M2-05, two reviews: mine and the parallel session's), people management and the Entra preset (M2-06/07, by the parallel session), onboarding (M2-09b), and the whole milestone. No P0 or P1 anywhere; every P2 was fixed, except F-14 (documented), and most P3 were fixed or recorded.
- Mutation checks: every new control was broken on purpose and the tests caught it. More than ten tests were found too weak on the way (for example a replay test hidden by the provider's own one-time code, a "sign-out" test that only proved the browser forgot the cookie, organization filters masked by row-level security) and were strengthened.
- Not run: coverage, load and performance, backup and restore, ACME on a public domain, a real Entra ID tenant, any provider other than a development Keycloak.

## Decisions

ADR-0011 (sessions, CSRF, identity-provider trust, organization resolution) is `Proposed`, like the other open ADRs. Choices made without the maintainer that they should review: Redis sessions with a hashed key and role and status read on every request; the Origin match as the login-CSRF defence; no group-to-role mapping; identity by `(issuer, subject)` and, for Entra, `oid`; the `process=worker` split so workers never hold the root key; Keycloak asks to confirm sign-out because Pharos stores no ID tokens.

## Open issues
