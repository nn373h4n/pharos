## F-44 (a stronger check after a restore) and F-02

Branch `fix/f-44-restore-check`.

- `scripts/restore.sh` builds a reference at the dump's schema version (the migrate image's migrations in a scratch database, then `pg_dump` and `pg_restore` into a second one, with the init script's database grants) and compares both with `scripts/restore/catalog.sql`. A first attempt that compared with the migrations directly showed false differences: PostgreSQL writes two CHECK constraints with different brackets after a dump and restore. Round-tripping the reference too removed them (0 differences between a restored dump and the reference; 441 lines at the time).
- `scripts/backup.sh` refuses a directory with a POSIX ACL and one under a parent others can write to without the sticky bit. On this host, a default ACL made a new dump `-rw-rw----+` while the directory stayed 700, so the mode check alone missed it.
- Independent security review (general-purpose agent with the `security-reviewer` instructions): two High and one Medium, all fixed. Each was shown on a real PostgreSQL before the fix: a schema named after the owner with a `!~~(name,name)` operator hid itself from both the old extra-schema check and the old catalog query; an extension made by the owner (`pgcrypto`) hid a `SECURITY DEFINER` function from the catalog; a `GRANT CREATE ON DATABASE` was not compared. Now names resolve in `pg_catalog` only, extensions other than `vector` or not owned by a superuser are refused, and the database's owner and grants are compared. Low items also fixed: the scratch databases are dropped with `FORCE`, a migration failure is shown, `has_acl` fails closed, and the docs list what is compared instead of "every grant".
- After the hardening, the compose smoke test caught a regression the unit tests did not: `alembic_version` was no longer found with the safe search path (now `public.alembic_version`).
- Checks: 93 unit tests PASS; 8 of 9 broken copies of the scripts caught (the ninth was a no-op control); `make test-compose` 151 PASS. The smoke test refuses a dump with an extra policy and grant, a dump with the hiding schema, an owner-made extension and extra database grants, and accepts the good dump.
- Not compared: rows. Hostile data (an extra administrator) still passes, and the docs say so.
- Process note: switching the working tree to another branch for a few seconds while a smoke run was going changed `scripts/restore.sh` under it. That run passed, but it was repeated cleanly (140 PASS); parallel work now goes in a separate worktree.

## F-44, second security review

PR #118 opened. A second independent review of the fixes found no Critical or High (the three earlier fixes hold, tried again on PostgreSQL 16) and two Medium and two Low, all fixed in the same branch:

- Medium: a TOC entry that starts with `COMMIT;` ends `pg_restore --single-transaction`, so a failed hostile restore can keep a default privilege, a `SECURITY DEFINER` function and a role setting while the database still has no table. The failure message said "nothing was restored"; it now says the database may be partly changed and the volume must be removed. The empty-database check also counts functions (not the extension's) and default privileges, so a retry on such a volume is refused.
- Medium: `catalog.sql` did not see `UNLOGGED`, replica identity, column collation, storage or compression, the database's template, connection and limit flags, comments or text search dictionaries. All are compared now; each change was shown seen on PostgreSQL 16, and the compose smoke test refuses a dump with an unlogged audit log.
- Low: the owner can change its own password. A digest of every role, membership and role setting (as the superuser, never printed) must be equal before and after the restore.
- Low: the private copy's directory and its parents now get backup.sh's ownership and sticky-bit checks.
- Left: names with control characters are printed unescaped in the comparison (noted in TASKS).
- Checks: 101 unit tests PASS; 4 broken copies of `restore.sh`, each caught by a test (the first try of one survived and the test was tightened: an unreadable digest is now refused before pg_restore); `make test-compose` 157 PASS; `make lint` 0.
